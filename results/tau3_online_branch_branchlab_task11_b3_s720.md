# τ³ 在线多分支执行试验

本试验在线执行一次公共前缀，在首次写入前、环境结果返回 Agent 的安全边界冻结状态；随后从同一消息历史启动多个隔离数据库分支，并共享不可变前缀的只读缓存。DeepSeek 不提供 KV-cache 克隆接口，因此模型侧只利用服务商自己的 prompt cache，未计作 BranchLab 的系统级共享收益。

## 配置

- 任务：τ³ airline task 11
- 模型：deepseek/deepseek-flash
- 事务模式：branchlab
- 分支数：3
- continuation 执行：parallel
- 公共前缀：15 条消息、6 次逻辑读、6 次物理读
- 切点：自动首次写意图

## 结果

| 2 | 722 | 1.000 | ✓ | 3.74 | 0.0010 | 0 | 0 | 0 |

## 聚合

- 成功分支：3/3
- 选中分支：2
- 实际总成本（公共前缀一次 + 切点 probe + 所有 continuation）：$0.0087
- 实测总墙钟时间：25.69s（公共阶段 20.05s + continuation 5.64s）
- 独立执行估算成本：$0.0172
- 公共前缀节省的物理读：12 次（66.7%）
- 全流程物理读：实际 6 次，独立分支估算 18 次，减少 66.7%

注意：这是在线多分支可执行性与共享机制的 pilot，不是最终统计结论；论文主表仍需覆盖更多任务、多个随机种子，并加入 2PL/OCC 的相同调度器对照。
