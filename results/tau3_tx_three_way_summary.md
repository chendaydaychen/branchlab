# τ³-bench 三组事务控制实验总结

## 实验对象

- 公开负载：τ³-bench `airline/base`。
- 固定上游提交：`b7ea9074c1cba482b30687fecdb5c8425fd6f619`。
- 模型：`deepseek/deepseek-flash`。
- 原始轨迹：26 个变更型任务，每任务 3 次，共 78 条。
- 包含实际写操作的轨迹：71 条。
- 对照组：2PL、严格 OCC、BranchLab。

适配器不修改 τ³ 上游代码，三组使用相同工具定义、初始数据、轨迹和 grader。事务控制发生在 `Environment.get_response()` 工具执行边界。

## 良性并发变化

每条轨迹在第一次写入前注入一个不会破坏待提交任务谓词的状态变化，例如：预订行李总数变化、用户地址变化或已确认航班价格下降。

| 方法 | 扰动应用/阻塞 | 接受 | 拒绝 | 误拒绝率 | 物理读取 | 共享命中 |
|---|---:|---:|---:|---:|---:|---:|
| 2PL | 0 / 71 | 71 | 0 | 0% | 642 | 0 |
| OCC | 71 / 0 | 0 | 71 | 100% | 615 | 0 |
| BranchLab | 71 / 0 | 71 | 0 | 0% | 252 | 390 |

BranchLab 在不阻塞良性并发变化的情况下完成了 130 次语义重基。跨三个候选分支共享确定性读取后，物理读取由 642 次降至 252 次，减少 60.7%。

2PL 的接受并不代表允许并发：它阻塞了全部 71 次扰动。严格 OCC 允许并发执行，但因为已读状态发生变化而拒绝全部提交。BranchLab 同时保留并发和正确提交。

## 有害并发变化

每条轨迹在第一次写入前破坏一个硬谓词，例如将目标预订标记为已取消，或移除新预订所需付款方式。

| 方法 | 扰动应用/阻塞 | 接受 | 拒绝 | 错误接受 |
|---|---:|---:|---:|---:|
| 2PL | 0 / 71 | 71 | 0 | 0（扰动被锁阻塞） |
| OCC | 71 / 0 | 0 | 71 | 0 |
| BranchLab | 71 / 0 | 0 | 71 | 0 |

BranchLab 没有为了提高接受率而放过有害变化：71/71 全部拒绝，错误接受为 0。

## 在线真实 LLM 冒烟

同一个 task 11 分别通过三个在线适配器执行，并由 τ³ 原生 grader 评分：

| 方法 | Reward | DB match | 时延 | API 成本 | 工具调用 |
|---|---:|---:|---:|---:|---:|
| 2PL | 1.0 | true | 30.76 s | $0.0087 | 7 |
| OCC | 1.0 | true | 31.45 s | $0.0084 | 7 |
| BranchLab | 1.0 | true | 30.38 s | $0.0087 | 5 |

三条在线轨迹均成功，证明适配层与 DeepSeek、τ³ 工具协议及 grader 兼容。但由于外部 LLM 即使温度为 0 仍生成了不同轨迹，该表只能作为集成冒烟，不能用于性能优劣结论。正式控制器比较采用上述相同轨迹配对回放。

## 当前能支持的结论

1. 真实 Agent 负载中存在大量分支共享机会；BranchLab 在三候选轨迹上减少了 60.7% 的物理读取。
2. 严格 OCC 在语义无害变化下产生 100% 误拒绝；BranchLab 通过写操作相关的任务谓词接受 71/71。
3. 对破坏硬谓词的变化，BranchLab 与 OCC 一样拒绝 71/71，未观察到错误接受。
4. 2PL 可以保证安全提交，但代价是阻塞所有并发扰动；BranchLab 在本实验中同时允许良性并发和安全提交。

## 证据边界

配对实验是对真实 τ³/DeepSeek 工具轨迹的确定性事务回放，能够隔离并发控制差异，但尚未测量在线多分支 LLM 调度、真实锁等待时间和失败后的自动重新规划。论文最终版本仍需增加：

- 在线多候选分支调度器；
- 同一对话前缀只调用一次模型的 LLM 分支机制；
- 2PL 锁等待与 OCC 重试的真实端到端时延；
- 至少 5 个运行种子和配对置信区间；
- 无共享、无语义重基、严格验证等消融。
